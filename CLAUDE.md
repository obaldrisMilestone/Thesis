## Project Overview

Computer vision thesis on **camera-to-floorplan localization** for Multi-Target Multi-Camera (MTMC) tracking. The goal is to estimate camera geometry (floor normal, camera height, pitch, roll) from surveillance video and compute a homography that maps the camera image to a 2D building floorplan.

Dataset: **Hospital_000** from MTMC_Tracking_2025 (31 cameras with calibration, GT extrinsic, videos, depth maps, and a floorplan `map.png`). Data lives at `dataset/MTMC_Tracking_2025/val/Hospital_000/`.

## Running Scripts

```bash
uv run python <script.py>   # run any script
uv add <package>            # add dependency
```

All scripts are standalone with hardcoded paths in a `CONFIGURATION` block at the top. No CLI arguments — edit the config section before running. GPU is auto-detected via `torch.cuda.is_available()`.

## Entry Points

Two parallel pipelines produce the same four-stage output — only Stage 2 differs:

**`end2end_homography.py`** — classical RANSAC pipeline:
1. **Floor geometry** — floor normal, camera height, pitch & roll via `MetricFloorNormalExtractor`
2. **Corner detection** — 3D room corners via `extract_room_corners()` (RANSAC wall planes + triple intersections)
3. **Corner matching** — detected corners matched to floorplan annotations by ray-direction angle
4. **Homography** — analytical floor-plane homography `H : camera pixel → floorplan pixel`

**`end2end_homography_DL.py`** — deep learning pipeline (drop-in replacement):
- Stages 1, 3, 4 are identical to the RANSAC version.
- Stage 2 runs `KeypointDINO` or `KeypointDINO_D` to get 2D pixel keypoints, then backprojects each through K⁻¹: `ray = K⁻¹ @ [u, v, 1]ᵀ`. These camera-space rays are treated as `corners_cam` for the rest of the pipeline — valid because matching is scale-invariant and height estimation computes its own scale from the known floorplan distance.
- Config: set `DL_MODEL` (`'dino_rgb'` / `'dino_d_rgb'`), `DL_CHECKPOINT`, `DL_THRESHOLD`.
- Outputs go to `end2end_out_DL/<CAMERA_ID>/` (not `end2end_out/`).

For the full mathematical derivation see **`PIPELINE.md`**.

## Pipeline Architecture

### Stage 1 — Temporal Segmentation (`segmentation/`)
- `mask2former_video.py` — `TemporalVideoSegmenter`: samples video frames, runs Mask2Former (ADE20K), accumulates masks across time via logical OR. Priority: floor > door > wall (resolves overlap).
- Output: `segmentation/temporal_masks/Camera_XX_temporal_bg.jpg` — colour-coded BGR
- `boundary_extraction.py` — wall-base boundary detection via HSV thresholding + Probabilistic Hough + collinear merge

### Stage 2 — Temporal Depth (`depth/`)
- `depth_anything_simp.py` — `TemporalDepthSegmenter`: runs DepthAnything on first/last frames, aggregates with EMA smoothing
- **Critical:** DepthAnything outputs *disparity*. The code inverts it: `depth = 1 / (disp_normalized + 0.05)`. Raw `.npy` files saved are already depth (not disparity).
- Output: `depth/temporal_depth2/Camera_XX_temporal_depth_raw.npy` (float32)

### Stage 3 — Floor Normal & Geometry (`geometry/`)
- `normals.py` — `MetricFloorNormalExtractor.extract_normal(depth, floor_mask, K)`: unprojects floor pixels to 3D, voxel-downsamples, fits plane with RANSAC. Adaptive thresholds scale with median depth so both metric and relative depth maps work.
- `corners_extraction.py` — `extract_room_corners(depth, floor_mask, wall_mask, K)`: unprojects 3D, fits up to 4 wall planes iteratively, intersects floor+wall+wall triples; filters by perpendicularity (dot < 0.5) and Z > 0. Adaptive RANSAC distance threshold = 5% of median scene depth.

### Stage 4 — Floorplan Annotation (`cameras_and_floorplans/`)
- `annotator_v2.py` — interactive matplotlib tool: floorplan (left) + camera image (right), click to annotate corresponding points; saves to `dataset/MTMC_Tracking_2025/annotations/val/Hospital_000/`
- `corner_matcher.py` — core matching module (no GT extrinsic, no scale inside):
  - `direction_attr_to_world_azimuth(deg)` — converts dataset `direction` attribute to world azimuth. The attribute uses a screen-space convention with a −90° offset; verified against Camera_0000 GT.
  - `build_rotation_matrix(world_azimuth_rad, pitch_deg, roll_deg)` — builds world-to-camera R. Convention verified: R from GT angles matches GT extrinsic R to float precision.
  - `match_corners(corners_cam, R, cam_world, ann_world)` — scale-invariant matching by 3D ray direction. `corners_cam` can be real 3D points OR backprojected pixel rays (K⁻¹ @ [u,v,1]) — only direction is used.
  - `match_pixel(u, v, K, R, cam_world, ann_world)` — convenience wrapper for a single 2D pixel.
  - `build_homography_pairs(matches, corners_cam, K, ann_pixels)` — builds parallel src/dst arrays for `cv2.findHomography`.

### Deep Learning Corner Detection (Experimental / Ablation)
Three model variants, each in their own subdirectory with `training.py` and `inference.py`:

- **`dino_rgb/`** — RGB-only: frozen DINOv2-S backbone + neck + decoder + focal-loss heatmap head (`KeypointDINO`)
- **`dino_d_rgb/`** — RGB-D: DINOv2-S (RGB) + trainable ResNet18 (1-ch depth) with late-fusion (`KeypointDINO_D`)
- **`detr/`** — KeypointDETR: DETR with keypoint MLP head instead of bounding-box head, Hungarian matching

All three use the same heatmap paradigm: Gaussian target → CenterNet-style focal loss → NMS peak extraction via `extract_keypoints()`. Training uses synthetic mock data (run `training.py` to generate). Checkpoints are stored at `<variant>/checkpoints/best_model.pth` and include the full `config` dict so the architecture can be reconstructed without manual parameter syncing.

**Loading note:** `end2end_homography_DL.py` loads training modules via `importlib.util.spec_from_file_location` to avoid namespace collisions (both `dino_rgb/training.py` and `dino_d_rgb/training.py` have the same filename).

### Evaluation (`geometry/compare_groundtruth.py`)
Compares predicted floor normals and camera heights against GT extrinsic. Outputs `geometry/evaluation_summary.json`.

## Key Conventions

**Calibration data structure** (`dataset/MTMC_Tracking_2025/val/Hospital_000/calibration.json`):

```python
with open('calibration.json') as f:
    data = json.load(f)
sensors = [s for s in data['sensors'] if s['type'] == 'camera']
cam = next(s for s in sensors if s['id'] == camera_id)

K   = np.array(cam['intrinsicMatrix'])   # 3×3
ext = np.array(cam['extrinsicMatrix'])   # 3×4  [R | t]
R, t = ext[:, :3], ext[:, 3]

# Independent fields (safe to use in estimation — not derived from extrinsic):
cam_xy  = np.array([cam['coordinates']['x'], cam['coordinates']['y']])  # world XY (metres)
yaw_deg = float(next(a['value'] for a in cam['attributes'] if a['name'] == 'direction'))
scale   = float(cam['scaleFactor'])          # floorplan pixels per metre
trans   = cam['translationToGlobalCoordinates']  # {'x': ..., 'y': ...}

# GT-only fields (for error reporting, never fed into estimation):
camera_position = -R.T @ t           # world-space camera centre
camera_height   = abs(camera_position[2])
```

**World ↔ floorplan pixel conversion:**
```
fp_x =  scale * (world_x + trans_x)
fp_y =  map_h - scale * (world_y + trans_y)
```

**Floor normal convention:** negate if `n[1] > 0` so it always points upward in camera space (Y axis points down in OpenCV convention).

**Mask colour encoding** (BGR, for HSV extraction downstream):
- Floor: green `[0, 255, 0]`
- Wall: red `[0, 0, 255]`
- Door: cyan `[255, 255, 0]`

**Depth vs. disparity:** After normalizing DepthAnything disparity to [0,1], `depth = 1 / (disp + 0.05)`.

**GT-free estimation principle:** The corner matcher and homography stages use only independently known fields (`coordinates`, `direction` attribute, `scaleFactor`, `translationToGlobalCoordinates`) — never the extrinsic matrix, which is reserved for error comparison only.
